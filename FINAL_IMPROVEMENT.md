# Final Technical Improvement

Citation placement, enforced rather than asked for.

## What was improved

Prompt v3 has asked for a citation after each factual sentence since HW4.
Rule 3 says it in those words: *"Cite inline, in square brackets, right
after the sentence that used it: [chunk_id]. Every factual sentence needs
one."*

The HW8 evaluation recorded what actually happened: *"Five of the six
answered cases put every citation at the end of the paragraph rather than
after the sentence it supports, and no check here notices."*
`outputs/quality_report.md` named it as problem 2, and its own next step 2
asked for a check that measures where a citation sits.

So the gap was never a missing rule. It was a rule the system stated and
never verified. This change adds the verification, one bounded repair
attempt, and a report that shows both.

## Why this was needed

The corpus answers questions about tool permissions, agent autonomy and
pre-deployment checks. A claim like *"grant only read access to specific
resources"* is worth acting on only if a reader can find the line behind
it. When every citation sits at the end of the paragraph, checking one
sentence means reading all five cited chunks, and there is no way to tell
which one was actually used.

The metric made it worse rather than surfacing it. `groundedness_good_rate`
read **100%** on that run, because it asks whether a cited id resolves to a
chunk the answer was given - never where the id sits. A number at its
maximum is the least likely thing anyone re-examines.

## What changed technically

- **`generation/citations.py`** - `sentences`, `ends_with_citation`,
  `uncited_sentences`, `claims`, and `rejection_reason`, which decides
  whether a repair may replace an answer. No sentence splitter was added to
  the dependencies; the boundary is one regex, and the version strings and
  addresses that would break a naive one are covered by tests.
- **`generation/prompts.py`** - `REPAIR_SYSTEM` and `render_repair`. Not a
  `PromptTemplate`: that class renders a question against chunks, this
  renders a finished answer against them.
- **`generation/answering.py`** - `place_citations`, the `repair_citations`
  switch, and a `FilteringRetriever` protocol so the pipeline names the one
  method it uses instead of a concrete retriever.
- **`models/generation.py`** - `CitationPlacement`, plus
  `citation_placement`, `generation_attempts`, `repair_note`,
  `uncited_count` and `uncited_before_repair` on `GroundedAnswer`.
- **evaluation layer** - four columns in the eval schema and the report
  generator, and a `citation_compliance_rate` metric beside
  `groundedness_good_rate`. The committed `outputs/eval_results.csv`
  predates them; see limitation 7.
- **`scripts/run_citation_comparison.py`** - answers every guidance case
  twice and writes `outputs/citation_comparison.md`.
- **`configs/base.yaml`** - `repair_citations`, and `--no-repair` on
  `scripts/rag_answer.py` to override it for one run.

The decision the whole layer rests on: **a repair is a candidate, not a
result.**

```
generate -> check placement
              |- every sentence cited ------------> ship it, one call
              `- some uncited -> repair once -> accept only if
                                    the claims are unchanged,
                                    no id was invented, and
                                    fewer sentences are uncited
                                 otherwise ship the first answer
```

A repair that fails any of the three is discarded and the original answer
ships with `citation_placement: unrepaired` and the reason in
`repair_note`. Nothing correct is ever withheld: the system fails closed on
truth - an invented chunk id - and degrades on presentation. A bundled
citation makes an answer harder to audit; it does not make it wrong, and
refusing to show a correct answer over formatting would push the reader to
a source with no corpus behind it at all.

## Before / after

Generated by `scripts/run_citation_comparison.py`; the full text of every
case is in `outputs/citation_comparison.md`.

### Case 1 - the improvement doing its job

```
Question: What is excessive agency and what causes it?

Before: Excessive Agency is a vulnerability ... manipulated outputs from
        an LLM. It typically arises ... through extensions or agents, and
        the root causes include excessive functionality, excessive
        permissions, and excessive autonomy. Common triggers ... in
        multi-agent systems [chunk_001, chunk_002, chunk_003].

        3 sentences, 2 with no citation. Three ids in one bracket at the
        end, so no claim can be traced to a chunk.

After:  ... manipulated outputs from an LLM [chunk_003][chunk_002]. It
        typically arises ... through extensions or agents [chunk_001], and
        the root causes include ... excessive autonomy [chunk_003]. Common
        triggers ... in multi-agent systems [chunk_002].

        3 sentences, 0 without a citation. All five placements check out
        against the chunks: chunk_002 holds the definition verbatim,
        chunk_003 the root-cause list, chunk_001 the extension delegation.
```

### Case 2 - the improvement reaching its ceiling

```
Question: What should we check before deploying an LLM application to
          production?

Before: four sentences, one citation at the end: [chunk_050].
After:  four sentences, four citations, all of them [chunk_050].
```

The count went from three uncited to zero and a reader gained nothing.
Retrieval found one usable chunk for this question - "Page 19" of the
governance checklist - and its five bullets are where all four sentences
come from. The placement is correct and discriminates nothing.

This case is here because it is the honest half of the result.

### Case 3 - the guardrail refusing a repair

From a development run, with an earlier repair prompt that read *"a
sentence built from two chunks and cited to one is wrong"*:

```
Repair returned: Excessive Agency is a vulnerability ... from an LLM. An
                 LLM-based system is often granted a degree of agency by
                 its developer - the ability to call functions or
                 interface with other systems via extensions ... The
                 decision over which extension to invoke may also be
                 delegated to an LLM 'agent' ... Agent-based systems will
                 typically make repeated calls to an LLM [chunk_001]. It
                 typically arises ...

Verdict:         rejected - "the claims changed"
Shipped:         the original answer, unchanged
```

The model satisfied "every sentence must map to a chunk" by pasting the
whole of `chunk_001` into the answer as three new sentences. Formally the
citations improved. The answer had been rewritten.

Without the acceptance check this would have shipped, and the report would
have counted it as a success.

## How the repair prompt was arrived at

Four wordings were tried against `e01`, one at a time, in the way HW4
compared `v2r`, `v2c` and `v3nr`:

| Prompt | The rule it added | Result |
|---|---|---|
| 1 | cite the chunks that support each sentence | 2 to 0 uncited, text intact, one co-citation missed |
| 2 | *"a sentence built from two chunks and cited to one is wrong"* | 2 to 3 uncited; `chunk_001` pasted in as three sentences |
| 3 | *"the sentences are fixed, only the brackets move"* | 2 to 2 uncited; `[a, b]` rewritten as `[a][b]`, nothing moved |
| 4 | names the starting state and asks for a transformation | 2 to 0 uncited, text intact, co-citation placed |

Both attempts to make the rule stricter made the output worse, and in two
different directions: one rewrote the answer to fit the measure, the other
did nothing while appearing to comply. Version 4 is in `prompts.py`.

The more useful conclusion is the one that survives whichever prompt wins:
versions 2 and 3 were both caught by `rejection_reason` and neither reached
a user. The design does not depend on the prompt being right.

## How it was tested

- **26 new unit tests** - 14 in `tests/unit/generation/test_citations.py`
  for the splitter, the placement check, all three rejection reasons, and
  the brackets that are not citations at all (`[0,1]`, `[above]`); 12 in
  `tests/unit/generation/test_answering.py` for the pipeline, including
  that a compliant answer costs one call, that an abstention is never sent
  for repair, that a replayed answer with a live repair reports a network
  call, and that a repair call which raises leaves the answer intact.
  Suite: **303 passing**, `ruff` clean.
- **The splitter was run over all twelve real answers** in
  `outputs/eval_results.csv` before it became library code. No false
  splits, including `1.2.9`, `nvd@nist.gov` and `#sec-conversational-ai`.
- **`scripts/run_citation_comparison.py`** answers seven guidance cases
  with the guardrail off and on. Both halves replay from
  `index/answers_cache.json`, so the table reproduces on a clean clone with
  no API key.

## Result

Over the four guidance cases that produce citations, across their fourteen
sentences:

| | Guardrail off | Guardrail on |
|---|---|---|
| Sentences ending without a citation | 7 | **0** |
| Answers meeting the sentence-level contract | 1 of 4 | **4 of 4** |
| Repairs refused | — | 0 on this run |
| Extra model calls | 0 | 1 per repaired answer, 3 in total |

The three abstentions are untouched and cost nothing: a refusal claims
nothing, so there is nothing to place. `e12`, which already met the
contract, is left alone at the cost of no second call.

## Remaining limitations

1. **Placement is not attribution.** Every check here asks where a citation
   sits, never whether the chunk supports the sentence. `e01` shows the two
   coming apart: the same repair prompt, model and `temperature: 0`
   produced `[chunk_003]` on one run and `[chunk_003][chunk_002]` on
   another, and the validator passed both. The second is correct and the
   first left a verbatim quotation uncredited.
2. **`temperature: 0` is not determinism.** Which ids land where varies
   between runs of an identical input. Placement compliance is stable;
   attribution is not.
3. **A single-source answer gains a number and not a reader.** `e03` is the
   worked example - see case 2 above.
4. **The sentence boundary is a regex.** It survives every answer this
   corpus has produced, and an abbreviation before a capitalised word
   ("U.S. Government") would split wrongly. None appears here, and nothing
   detects one if it does.
5. **The triage envelope is not audited.** `retrieve_guidance` is placed
   like any other answer, but the composed triage reply is not: four of its
   eight sentences come from tool output and have no chunk to cite.
   Auditing the finished text would report seven violations against a
   correct run.
6. **A repair that fails is a repair that did not happen.** The second
   call is wrapped: transport errors, rate limits and unparseable bodies
   all end with the first answer shipping and `repair_note` saying which.
   The catch is deliberately broad, because an unlisted exception losing a
   correct answer is the one failure this layer exists to prevent.
7. **`orchestration/pipeline.py` is out of scope.** The HW5 tool route
   answers from a tool observation and carries no chunk citations, so the
   guardrail neither runs there nor should.
8. **`outputs/eval_results.md` still describes the system as HW8 submitted
   it.** Regenerating it with `--live` would rewrite six cached answers and
   invalidate the hand-written judgements in `configs/eval_cases.yaml`. The
   new columns and `citation_compliance_rate` are in the code and appear
   the next time that report is regenerated deliberately.
9. **Cost.** A non-compliant answer costs a second model call, and a
   refused repair costs it for nothing. The budget is one attempt, fixed in
   code rather than configurable, because an unbounded repair loop is a
   worse failure than a bundled citation.

The analysis behind these is in `configs/citation_conclusions.md`, appended
to `outputs/citation_comparison.md` on every run.
